# Crown Contract Summarizer

Тестовое задание для компании Crown: FastAPI-сервис принимает PDF-файл государственного контракта и с помощью локальной LLM через Ollama возвращает краткую структурированную выжимку:

- сумму контракта;
- основной срок выполнения, поставки или оказания услуг;
- ключевые требования и обязанности исполнителя;
- штрафы, пени и другие условия ответственности.

Для каждого результата сервис указывает номер пункта и страницы исходного документа. Если требуемая информация отсутствует, возвращается `null` или пустой список — модель не должна дополнять документ предполагаемыми сведениями.

## Технологии

- Python 3.12;
- FastAPI и Uvicorn;
- Pydantic;
- pypdf;
- httpx;
- Ollama;
- Qwen 3 8B;
- uv для управления зависимостями.

## Логика решения

Обработка документа состоит из следующих этапов:

1. API проверяет расширение, MIME-тип, PDF-заголовок и размер файла. Максимальный размер — 25 МБ.
2. `pypdf` извлекает текст отдельно с каждой страницы, сохраняя её номер.
3. Текст нормализуется и разделяется на пункты договора по нумерации. Если структура документа не распознана, формируются текстовые окна с перекрытием.
4. Каждый фрагмент оценивается по ключевым словам и устойчивым договорным формулировкам отдельно для суммы, сроков, требований и штрафов.
5. Для каждой категории выбираются наиболее релевантные фрагменты.
6. Категории последовательно отправляются в Ollama. Последовательная обработка уменьшает потребление памяти на одной машине.
7. Ollama возвращает структурированный JSON и идентификаторы использованных фрагментов.
8. Приложение самостоятельно преобразует идентификаторы в номера пунктов и страниц. Ответы с неизвестными источниками отклоняются.
9. При пустом, повреждённом или временно некорректном ответе Ollama выполняется одна повторная попытка.

Сервис не отправляет в модель весь документ целиком. Предварительный отбор уменьшает контекст и помогает не спутать цену контракта с обеспечением, а основной срок исполнения — со сроками оплаты, приёмки, гарантии или устранения недостатков.

## Установка

Установите [uv](https://docs.astral.sh/uv/) и [Ollama](https://ollama.com/), затем загрузите модель:

```bash
ollama pull qwen3:8b
```

Установите зависимости проекта:

```bash
uv sync
```

Создайте `.env` на основе `.env.example`:

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:8b
OLLAMA_TIMEOUT_SECONDS=300
OLLAMA_TEMPERATURE=0
OLLAMA_MAX_FRAGMENT_CHARS=6000
OLLAMA_MAX_FRAGMENTS_PER_CATEGORY=3
OLLAMA_NUM_PREDICT=1600
```

## Запуск

Запустите Ollama:

```bash
ollama serve
```

В другом терминале запустите API:

```bash
uv run uvicorn main:app --host 0.0.0.0 --port 8000
```

После запуска доступны:

- Swagger UI: <http://127.0.0.1:8000/docs>;
- проверка состояния: <http://127.0.0.1:8000/health>.

## Использование API

### Проверка состояния

```http
GET /health
```

Ответ:

```json
{
  "status": "ok"
}
```

### Анализ контракта

```http
POST /summarize_contract
Content-Type: multipart/form-data
```

Параметр `file` должен содержать PDF с текстовым слоем.

Пример запроса:

```bash
curl -X POST "http://127.0.0.1:8000/summarize_contract" \
  -H "accept: application/json" \
  -F "file=@/path/to/contract.pdf;type=application/pdf"
```

Сокращённый пример ответа:

```json
{
  "valid": true,
  "filename": "contract.pdf",
  "content_type": "application/pdf",
  "size_kb": 125.4,
  "page_count": 17,
  "extracted_pages": 17,
  "processed_fragments": 12,
  "processed_fragments_by_category": {
    "amount": 3,
    "terms": 3,
    "requirements": 3,
    "penalties": 3
  },
  "encrypted": false,
  "model": "qwen3:8b",
  "summary": {
    "contract_amount": {
      "value": "1 188 399,30 рублей",
      "sources": [
        {
          "clause": "2.2",
          "pages": [2]
        }
      ]
    },
    "performance_terms": [
      {
        "value": "Поставка товара осуществляется в срок до 30 сентября 2026 г.",
```

Поля `contractor_requirements` и `penalties` в примере сокращены. В реальном ответе они содержат найденные условия и ссылки на исходные пункты.

## Обработка ошибок

Сервис возвращает понятные HTTP-ошибки в следующих случаях:

- загружен не PDF или файл повреждён;
- файл пустой или превышает 25 МБ;
- PDF не содержит извлекаемого текста;
- Ollama не запущена или указанная модель не установлена;
- модель превысила тайм-аут;
- модель дважды вернула некорректный JSON или неизвестные источники.

Пример ответа для PDF без текстового слоя:

```json
{
  "detail": "PDF has no extractable text. OCR is required for scanned documents."
}
```

## Ограничения

- OCR не реализован, поэтому отсканированные документы без текстового слоя не поддерживаются.
- Качество зависит от структуры PDF и корректности извлечения текста библиотекой `pypdf`.
- Сервис анализирует итоговую цену контракта, а не НМЦК и не размер обеспечения.
- В заключённых контрактах извлекаются обязанности исполнителя. Квалификационные требования к участнику закупки могут находиться в других документах.
- Время обработки зависит от оборудования, объёма фрагментов и выбранной модели. При локальном тестировании приложенные документы обрабатывались примерно за 25–70 секунд.
- `/health` сообщает о работе FastAPI, но отдельно не проверяет готовность Ollama.
